Architecture approach for the app

The biggest decision: how to structure admin CMS vs owner portal in a single Next.js codebase.

A

Single app, route-based separation (Recommended)

One Next.js 15 app. Admin lives at /admin/..., owner portal at /portal/.... Shared Supabase backend. Middleware handles role-based access — admins can't reach /portal and owners can't reach /admin.


Pros

  • One codebase, one deployment
  • Shared auth, DB, storage config
  • Simple to reason about

Cons

  • Must be careful with middleware routing
  • Admin bundle ships to same domain as portal
B

Two separate Next.js apps

Admin CMS deployed at admin.elpekas.lt, owner portal at app.elpekas.lt. Both connect to the same Supabase project. Separate repos or a monorepo with Turborepo.


Pros

  • Complete isolation between apps
  • Different deploy cadences possible

Cons

  • 2× the config, 2× the deployments
  • Shared code needs a package or copy-paste
  • More overhead for a project this size
C

Single app, subdomain routing via Next.js middleware

One codebase, but middleware routes admin.elpekas.lt to admin pages and app.elpekas.lt (or elpekas.lt) to owner portal. Best of both — clean URLs, one deploy.


Pros

  • Clean subdomains without two codebases
  • Professional URL separation

Cons

  • Slightly more complex middleware
  • Needs wildcard domain on Vercel
